# Who Is Who API

This is a separate, global directory, following the existing leadership module. It does not alter existing pages, leadership records, or API contracts. The website must render the new public endpoint to use this feature; existing static HTML is not automatically converted.

All seven business fields are stored as strings, including the validated `YYYY-MM-DD` retirement date. An unset retirement date is null.

Required create fields: `officerName`, `officerName_hi`, `designation`, `designation_hi`, `phone`, `email`. Designation, phone, and email fields are free-form, non-empty text fields so each can contain multiple comma-separated values. Email format is not validated. Supplied text, including `[dot]` and `[at]`, is preserved apart from trimming surrounding whitespace.

Optional fields: `retirementDate` (`YYYY-MM-DD` or null), `displayOrder` (nonnegative integer, default 0), `isActive` (boolean, default true). Updates are partial; omitted fields remain unchanged. Set `retirementDate: null` to remove the cutoff. Missing retirement dates impose no cutoff. Invalid dates, empty required fields, null required fields, and nonboolean active flags are rejected.

An officer remains publicly visible through the retirement date in Asia/Kolkata. From midnight the next day the entire entry is excluded from both public list and detail endpoints. Inactive and deleted entries are also excluded. Retirement dates and audit fields are not exposed publicly. Admin reads include retired/inactive officers. Deletes are soft deletes; edits and deletion are audited in the same transaction.

| Method | Route                        | Purpose                         |
| ------ | ---------------------------- | ------------------------------- |
| POST   | `/api/who-is-who`            | Create                          |
| GET    | `/api/who-is-who`            | Admin list: page, limit, search |
| GET    | `/api/who-is-who/:id`        | Admin detail                    |
| POST   | `/api/who-is-who/:id/update` | Partial update                  |
| POST   | `/api/who-is-who/:id/delete` | Soft delete                     |
| GET    | `/api/public/who-is-who`     | Website list                    |
| GET    | `/api/public/who-is-who/:id` | Website detail                  |

Detail/update/delete also accept `uuid/:uuid` in place of `:id`. Lists sort by `displayOrder`, then numeric ID; serial numbers can be generated by the website. Admin list uses the standard `items`/`meta` pagination response, wrapped in the application's standard response envelope. Public list returns an array in `data`.

Admin routes require JWT authentication and the corresponding `WHO_IS_WHO_CREATE`, `WHO_IS_WHO_VIEW`, `WHO_IS_WHO_UPDATE`, or `WHO_IS_WHO_DELETE` permission. Defaults follow leadership: all five existing roles receive these permissions. Entries are global, not organization scoped.

## Deployment

Run `npx prisma migrate deploy`, then `npx prisma generate` and `npm run build` in the deployment workflow. The migration creates a new table and new permissions; existing content is unchanged. Review all pending migrations first, including the existing UUID migrations. No migration or sample-data insertion was applied to a live database as part of this implementation.

Postman examples are in the `Who Is Who` folder. Set `officerId` or `officerUuid` from the create response.
